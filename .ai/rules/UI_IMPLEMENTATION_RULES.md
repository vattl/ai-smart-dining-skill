# UI Implementation Rules

- Prototype design must be implementation-aware.
- Production implementation must be prototype-faithful.
- Technical constraints may require adaptation, but never silent visual or interaction deviation.
- UI work must inspect the project's real framework, component library, font stack, icons and styling system before prototype decisions.
- When backend/domain semantics change, inspect whether UI labels, controls, disabled states, filters, validation and displayed fields also need to change.
- Production implementation is translation, not redesign.
