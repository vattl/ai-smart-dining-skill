# Change Rules

1. Final State over patch thinking.
2. Every affected element must be classified.
3. Replacement means replacement.
4. Removal is part of Definition of Done.
5. UI changes must inspect before/after structure, shared layout, CSS, responsive rules, and conditional rendering.
6. Replacement changes require negative acceptance criteria.
7. Perform legacy scans before completion.
8. Old + new active after supposed replacement = PARTIAL.
9. Old implementation may remain only for explicit migration/fallback/compatibility reasons.
10. Completion requires target state exists + obsolete state retired + preserved behavior still works.
