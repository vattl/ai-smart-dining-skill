# Coding Rules

- Understand before editing.
- Search before creating new abstractions.
- Prefer minimal safe change.
- Avoid unrelated refactors/renames/formatting/dependency changes.
- Preserve existing behavior only when it is intended to remain.
- Do not add speculative architecture.
- Do not swallow errors or hide failures.
- Consider concurrency, idempotency, transaction boundaries, and event ordering where relevant.
- Do not hardcode secrets or environment-specific credentials.
- Comments should explain WHY, not obvious WHAT.
- Code existence is not completion; verify Definition of Done and Diff state.
