# /init

Initialize a new software project for long-term AI-driven development.

Input: `$ARGUMENTS`

## Workflow

IDEA → RESEARCH → PRODUCT ANALYSIS → GO/NO-GO → PRD APPROVAL → ARCHITECTURE → DATABASE → API → FEATURES → TASKS → PROJECT_STATE

## Steps

1. Create a Project Charter with problem evidence, target users, value and constraints.
2. Complete decision-relevant user/market/competitor research with sources and confidence.
3. Analyze options, value/cost/risk, MVP boundary and measurable success targets.
4. Record an explicit GO decision before treating the initiative as approved.
5. Produce the PRD and trace requirements to evidence, metrics and acceptance.
6. Record explicit PRD approval.
7. Design the simplest architecture, data model and contracts that safely support the approved MVP.
8. Create features, vertical tasks, PROJECT_STATE and interruption-safe cursor.
9. Validate product, architecture, data, API, test and release assumptions for consistency.

Do not begin broad implementation before the project foundation is sufficiently defined.

## Interruption-Safe Initialization

Create `docs/EXECUTION_CURSOR.md`.

For the first non-trivial active task, initialize:

- Active Task
- Current Step
- Expected Outcome
- Relevant Files when known
- Next Verification

Do not create artificial step detail before implementation context exists.
