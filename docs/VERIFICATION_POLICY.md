# Verification Policy

## Completion Truth

`DONE` is not a narrative statement. It is the result of verified requirement coverage.

For material work, verification should answer:

1. What was originally requested?
2. What capability/rule changed?
3. Which consumers depend on it?
4. Which code actually changed?
5. Which tests/checks were executed?
6. Was any fake/mock/placeholder used in a production path?
7. What remains unverified?
8. Which commit contains the completed task?

Use `/verify` for STRUCTURAL/CRITICAL work, repeated repairs, low-confidence execution, or when completion quality is in doubt.
